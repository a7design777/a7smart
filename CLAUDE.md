# a7smart

Веб-дашборд керування 2–3 квартирами. Прод: **smart.zvyazok.com**

> **Спершу прочитай [ARCHITECTURE.md](ARCHITECTURE.md)** — там потік даних,
> обґрунтування рішень і перелік пасток. Тут лише найнеобхідніше.

## Домен та контекст

- Пристрої — **виключно хмарні API, без локальних шлюзів**. Жодного заліза
  вдома: це вимога користувача, не тимчасове обмеження.
- Провайдери: **Tuya** (основний, читання й керування) та **Remihome/Remica**
  (необов'язковий, недокументований інтерфейс їхнього веб-порталу).
- Користувачі — власник і сім'я. Мультитенантності, ролей і реєстрації
  **немає за задумом**. Один спільний пароль.

## Обмеження, які визначають усе

**Сервер 1 vCPU / 1 GB RAM**, спільний з Traefik, n8n, flowise та a7cms:

- `mem_limit: 256m` обов'язковий, інакше витісняються сусіди
- образ збирається в GitHub Actions, не на сервері
- важкі залежності не додавати. Home Assistant свого часу відкинуто саме тому

**Квота Tuya API скінченна.** Стани читаються з кешу сервера. Будь-яка фіча,
що ходить у хмару на кожен рендер, — помилка.

## Ключові файли

| Файл | Роль |
|---|---|
| `server/src/poller.ts` | Фоновий опитувач обох джерел, кеш станів, `refreshDevice` |
| `server/src/tuya/client.ts` | Підпис запитів Tuya (HMAC-SHA256). Без залежностей |
| `server/src/tuya/devices.ts` | Три стратегії читання статусів + ізоляція проблемних пристроїв |
| `server/src/tuya/normalize.ts` | **Мапінг DP-кодів Tuya.** Бракує показника — правити тут |
| `server/src/remihome/client.ts` | Логін і сесія порталу Remihome |
| `server/src/remihome/normalize.ts` | Нормалізація з метаданих самого пристрою |
| `server/src/scenes.ts` | Виконання сценаріїв |
| `web/src/useDragSort.ts`, `useDragAssign.ts` | Перетягування на Pointer Events |

## Команди

```bash
npm run typecheck && npm run lint && npm run build   # після кожної зміни
npm run db:migrate      # міграції в Neon, з локальної машини
npm run status          # що зараз у базі
npm run tuya:probe      # сирі коди Tuya, перевірка камер
npm run remihome:probe  # структура відповідей Remihome
```

## Правила роботи

- Перед зміною коду — прочитати суміжні файли, зрозуміти патерни.
- Після кожної зміни — `npm run typecheck && npm run lint && npm run build`.
  Не казати «готово» без перевірки.
- Не вигадувати API — звіряти через `tuya:probe` / `remihome:probe`
  або developer.tuya.com.
- **Перед діагностикою будь-якої поломки на проді — звірити `version`
  у `/api/health` з останнім комітом.** Тричі втрачали час на хибні діагнози
  через те, що `docker pull` мовчки віддавав старий образ.
- Відповідати українською.

## Обережно: це керує реальним житлом

Команди на пристрої вмикають і вимикають опалення, світло й розетки у
квартирах, де живуть люди. Не надсилати команди «для перевірки» без явного
дозволу користувача. Формат запитів можна з'ясувати читанням (probe-скрипти,
код порталу) — так і робилося досі.
