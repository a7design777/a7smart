# a7smart

Веб-дашборд керування 2–3 квартирами. Прод: **smart.zvyazok.com**

## Домен та контекст

- Пристрої — **виключно Tuya Wi-Fi, без локальних шлюзів**. Жодного заліза вдома:
  все йде через хмару Tuya. Це вимога користувача, не тимчасове обмеження.
- Користувачі — власник і сім'я. Мультитенантності, ролей і реєстрації **немає
  за задумом**. Один спільний пароль.
- Камери icSee замінюються на Tuya: icSee використовує закритий P2P-протокол,
  без локального пристрою потік із них отримати неможливо.

## Архітектура

Один Node-контейнер віддає і API (Hono), і зібраний React. Історія — Neon Postgres.
Розгортається на `159.223.224.106` за **наявним Traefik** (мережа `n8n-docker_default`),
поруч із n8n, flowise та a7cms.

**Обмеження сервера: 1 vCPU / 1 GB RAM.** Це головний технічний контекст:
- `mem_limit: 256m` — обов'язковий, інакше витісняються сусіди
- Docker-образ збирається в GitHub Actions, не на сервері
- Важкі залежності не додавати. Home Assistant свого часу відкинуто саме тому

## Провайдери

**Tuya** — основний, керування й читання. **Remihome (Remica)** — необов'язковий,
**лише читання**: ендпоїнт запису в їхньому API не знайдений.

Remihome використовує недокументований інтерфейс власного веб-порталу
(`proxy.remihome.es`): логін формою → сесійна cookie → JSON. Може зламатися
при оновленні порталу, тому провайдер вимикається відсутністю `REMIHOME_*`
у конфізі, а його відмова ніколи не валить Tuya.

Приємна відмінність: Remihome самоописовий — `type.properties` містить формат,
режим (`display`/`exec`) і перелік станів, тому нормалізація будується з
метаданих, а не з ручного списку кодів. Значення приходять у реальних
одиницях, без масштабування.

## Ключові файли

| Файл | Роль |
|---|---|
| `server/src/tuya/client.ts` | Підпис запитів Tuya (HMAC-SHA256), кеш токена. Без залежностей |
| `server/src/tuya/normalize.ts` | **Мапінг DP-кодів Tuya → доменна модель.** Бракує показника на дашборді — правити тут |
| `server/src/remihome/client.ts` | Логін і сесія порталу Remihome |
| `server/src/remihome/normalize.ts` | Нормалізація Remihome з його ж метаданих |
| `server/src/poller.ts` | Фоновий опитувач обох джерел + кеш станів + `/api/health` |
| `server/src/scripts/probe.ts` | Розвідка сирих кодів Tuya |
| `server/src/scripts/probe-remihome.ts` | Те саме для Remihome |

## Правила роботи

- Перед зміною коду — прочитати суміжні файли, зрозуміти патерни.
- Після кожної зміни — `npm run typecheck && npm run lint && npm run build`.
  Не казати «готово» без перевірки.
- Не вигадувати API Tuya — звірятися з developer.tuya.com або через `tuya:probe`.
- Відповідати українською.

## Пастки

1. **Термін дії IoT Core.** Безкоштовний, але скінченний, продовжується вручну
   через *Cloud → My Services*. Коли спливе — Tuya віддає 1010/1106 і дашборд
   «ламається» без видимої причини. `/api/health` показує це окремим прапорцем
   `tuyaAuthProblem`.
2. **Квота API-викликів.** `POLL_INTERVAL_MS` прямо на неї впливає. Не знижувати
   без потреби; будь-яка нова фіча, що ходить у Tuya на кожен рендер, — помилка.
3. **DP-коди різні для кожної моделі.** Не вгадувати, запускати `npm run tuya:probe`.
4. **Офіційний Tuya SDK не використовуємо** — покинутий з 2022, тягне вразливий
   axios 0.21. Підпис реалізовано власноруч, залежностей нуль.
5. **Затримка керування 0.5–2 с** — наслідок хмарного шляху, не баг. Тому в UI
   оптимістичні оновлення та дебаунс на стрілках температури.
